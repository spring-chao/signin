# 班会开始前可信名单自动同步

按用户后续要求，现改为签到开放前约2分钟同步一次。`classRosterBeforeStartOnce` 每分钟检查场次时间，仅在开放前2分钟窗口内按班级组织ID读取可信名单；成功后按本次开放时间记录完成，不再重复读取或更新。临时失败仅在开放前重试；主动修改开放时间后允许在新时间前同步一次。原提前24小时每5分钟同步的规则及触发器取消。

仅处理已确认、未关闭、未开始的班会；取消、草稿、课程、未关联班级、指定小组和已发生签到的场次不处理。上午、下午、空巴各场次单独判断，已开始的上午不会妨碍未开始的下午更新。事务内的短时任务占用防止重叠触发；崩溃后占用过期仍可在开放前重试。

名单来源、组织范围、人数及资料质量沿用统一平台严格校验。按平台学员ID及学员编号匹配，增补新成员并刷新本班成员姓名、企业、小组等资料；保留既有报名、请假/迟到跟进、实际参加人和签到事实，不删除转出人员的历史报名。身份不唯一或来源不可用时停止该场次，后续任务重试。

新增报名使用确定的文档ID防止重复任务产生重复人员；每次写入在文档事务内再次核验班级、生命周期和签到开放时间，核验并保护并发签到。更新与不含个人内容的审计同事务提交，失败不会留下该成员的半次更新。任务优先处理最接近开放时间的活动，控制总调用时长，返回增补、更新、失败及延后数量，不返回姓名、手机号或上游错误正文。

自动名单使用独立命名的触发器，不启用历史签到重试。本次不创建数据库表或云函数，不调整签到时间/规则、学分或员工权限。发布时更新现有签到函数代码，保留环境变量、权限、运行配置与每日零点同步触发器；替换名单同步触发器，只进入本次自动名单分支。回退时关闭新触发器、恢复原始代码包和原名单触发器，已同步的报名资料保留，不回滚业务事实。

隔离验证：自动同步12种场景（重复、并发、可信源异常、资料质量异常、边界、已签到、审计回滚等）；原签到API、课程/团队、平台权限和264项并发集成断言、打包、共享测试集合隔离、官方SDK事务契约、导入解析与公开页面回归通过。生产验收单独记录，不以合成测试替代真实定时执行。
