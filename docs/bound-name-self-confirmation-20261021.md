# 绑定姓名一致时本人确认签到

用户已明确授权完善全部需求后上线：本人已绑定小程序，报名缺手机号且平台存在多个同名学长时，也应能确认本人签到。

原逻辑要求空手机号报名姓名在平台所有有效学员中唯一，导致“王超”等同名学长被挡在无本人报名页面。平台现在核验绑定的精确有效 ID、编号和姓名，无需全库姓名唯一。签到服务只在未关联其他平台身份、姓名一致的报名中作本人确认；记录 identity_match=BOUND_NAME_SELF_CONFIRMATION 和确认时间，不宣称缺少的手机号核验通过。已有不同 ID/编号、姓名不一致、真正团队名额等不被静默覆盖。

同一绑定人有多条同名报名时只选择一条：优先本人已经签到的原记录，其次参考相同班级，最后稳定选择一个未被其他学员占用的名额。不一次签到所有同名人。事务内再次核验报名身份，已有到场事实先校验归属；姓名渠道先签到、绑定渠道后确认时保留原签到时间，补充明确本人确认的身份并重新排队同步。报名总数不增加。并发和重复点击保持一条事实。

主平台上下文已签发的短效 native ticket 可以为缺手机号报名复用已验证绑定，在平台暂时不可用时继续写入签到事实。普通后台导入仍依靠姓名+手机号作确定性映射。平台 API 须先发布，随后发布独立签到服务；小程序按钮文案修改另随微信代码包发布，服务端匹配改进兼容既有正式小程序。

隔离测试：平台联调256断言、姓名/课程签到、官方 CloudBase 数据库SDK事务合约、独立和共享测试隔离、公共页面与导入解析均通过。没有为真实学长执行签到或改写报名。生产状态以发布核验记录为准。
