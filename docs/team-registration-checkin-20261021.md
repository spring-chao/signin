# 独立报名签到识别修复（不部署）

旧逻辑仅凭同公司多条报名且缺少平台学员 ID/编号，推断为团队，导致不同姓名的个人报名被姓名查询排除。现改为仅明确团队角色或同公司、同联系人、同联系方式重复占位时判断为团队。

绑定本人遇到缺手机号的历史普通报名时，通过平台受保护的 registration-identities 接口带入服务端已核实的 bound_member；平台只有在姓名对应唯一有效学员且 ID/编号均一致时返回匹配。仍不允许姓名歧义、非空错误手机号、已有冲突关联或真实团队自动归入本人。

查询不写入报名或签到。确认重读报名并在事务内检查身份是否变化；同报名的扫码、绑定及并发操作保留一个签到事实。真实团队原有实际参加人确认流程不变。

此修复依赖主平台对应 API 变更，须先发布兼容 bound_member 的 API，再发布签到组件。本任务明确不部署、不查询或补写真实报名／签到、不触发生产发布流程。隔离测试使用合成姓名和名单。
