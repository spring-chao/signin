# 姓名一致的团队报名签到与场次排序

用户明确要求：无论报名渠道，只要本场报名名单已有姓名，就能扫码确认本人签到；当前可签到场次靠前，未开放和结束的场次排后。

原生及平台姓名查找原先排除了所有团队名额，甚至已绑定姓名与该行一致也返回备用流程。现在团队标记不再阻止同名本人确认。已绑定身份仍校验ID/编号且只选一条报名；未绑定人员使用既有姓名候选与短时选择凭证。实际参加人已变为他人的名额不可按原联系人姓名占用，事务中再次检查姓名及既有身份，保留原报名人与实际参加人。

相同企业、重复联系人等旧团队识别仅作名额提示，不作为扫码本人确认的阻断条件。不同实际参加人使用其他团队名额的既有流程保持，人工签到权限与身份边界不扩大。

当天已确认活动按可签到、未开放、已结束排序，取消或草稿不公开。结束场次仅显示状态，不能借排序变化绕过时间门禁；未来业务日期不混入今日列表。H5、服务端与小程序保持一致。

隔离验证覆盖显式团队、重复名额、空手机号有效原生授权、并发/重复确认只有一条事实、未绑定姓名候选、不同实际参加人拒绝、未开放/结束列表排序与不可签到。无生产签到写入或报名清理。
